# 普通个人微信长期记忆 AI：Codex 开发任务书

整理日期：2026-10-01  
状态：需求与开发交接文件；尚未启动 Codex，尚未在用户电脑或微信账号上验证。

## 1. 项目目标与已确认条件

这是一个全新的独立项目，不引用用户的其他项目，不假设能访问此前的 ChatGPT 聊天记录。

用户已经明确确认：

- 必须使用一个真正的普通个人微信账号，而不是企业微信、公众号、小程序、微信客服或官方机器人聊天入口。
- 用户用自己的日常微信号，与另一个由本人控制的普通微信号互加好友，在正常好友私聊中与 AI 对话。
- AI 应支持长期互动，能够记住用户偏好、延续话题；不能只是每条消息独立问答。
- 用户有一台可以用于本项目、能够较长时间开机的 Windows 电脑。
- 用户希望把方案交给 Codex，由 Codex 主导开发、创建文件、调试和测试，而不是让用户逐段手写代码。

尚未确认：Windows 与微信客户端的具体版本、是否已登录第二个个人号、模型服务商及凭据、预算、具体角色风格。能在授权工作区与环境内安全检查的内容，先自行检查；不要再次询问已经确认的需求。凭据由用户在本机安全配置，不要求粘贴进聊天。

## 2. 工作分工与执行原则

Codex 负责技术核验、架构、实现、依赖与配置、自动化测试、运行脚本、中文说明和故障定位。

用户仅承担确实需要本人完成的步骤，例如安装授权、微信扫码登录、确认唯一的测试联系人、在本机配置模型凭据，以及实机聊天验收。

不要只回复一篇教程。先检查当前工作目录，在其中执行可完成的开发任务；如果缺少真实微信环境或模型凭据，继续完成模拟适配器、核心逻辑与测试，并清楚报告尚未实测的部分。

本文件是需求交接，不是已经验证通过的代码级实施方案。环境核验后，创建或更新 `AGENTS.md`、`docs/PLAN.md` 和 `docs/STATUS.md`，记录确定的技术选择、实际进度、测试证据和下一步。

## 3. 候选架构，不把未经验证的组件当成既定事实

```text
用户日常微信号
    ↕ 正常好友私聊
用户控制的独立普通微信号
    ↕ Windows 微信客户端
可替换的微信消息适配器
    ↕ 白名单、顺序队列、去重、发送保护
对话编排层 / Agent
    ↕ 长期记忆与会话管理
可配置的大模型服务
```

上一轮方案提出：用 wxauto 类 Windows 桌面自动化项目作为接入候选，以 OpenClaw 作为 Agent 候选，GPT 作为模型候选。

这些是候选，不是已验证结论：

- 开发前查阅候选项目的上游仓库、正式文档、许可证和当前维护状态，核对实际微信客户端版本。
- 不直接沿用上一轮提及的精确版本号、维护状态、接口路径或兼容性结论，不编造 SDK 方法。
- 优先验证正常登录下的桌面自动化；不要采用凭据窃取、破解登录、绕过风控或未经许可访问账号的方案。
- 不承诺“绝不封号”或“永久兼容”。核验平台限制，向用户说明个人号自动化的实际风险。
- OpenClaw 能否适用，必须验证它的受支持接口、权限边界、Windows 部署方式及会话管理。不要直接暴露高权限网关到公网。
- 如果 OpenClaw 使首版明显复杂化，可以提出轻量对话服务替代方案；先说明取舍，不把替代路线伪装成原方案已实现。
- 微信适配器、记忆层和模型层须解耦；更换模型或接入工具不应丢失已有记忆。

供核验的候选入口（并非兼容性证明）：`https://docs.wxauto.org/`、`https://docs.openclaw.ai/`。实际选择须记录一手来源、查阅日期和实测结果。

## 4. 第一版范围与默认边界

第一版只实现指定好友的一对一中文文字聊天、可持久化记忆，以及安全的启动、暂停和停止。

不默认实现：群聊、自动加好友、群发、朋友圈、支付、文件执行、任意系统命令、自动操作其他联系人、语音与图片理解。

主动问候仅作为后续扩展点，默认关闭。将来启用前需单独确定时区、安静时段、频率和触发规则。

运行时聊天 Agent 与开发者 Codex 的权限要分开：开发者可在授权工作区开发，不能据此授予微信聊天 Agent 相同的电脑操作权限。

## 5. 分阶段交付

### 阶段 A：环境核验与普通个人号收发验证

目标：证明真实普通个人号通道可用，而不是先搭建完整 AI 后才发现无法接入。

- [ ] 检查 Windows、Python 等必要运行时和当前目录；不覆盖既有文件，不自动进行系统级升级或降级。
- [ ] 核对微信客户端版本和候选适配器兼容性，形成 `docs/COMPATIBILITY.md`，区分文档声明和本机实测。
- [ ] 创建最小项目、配置校验、模拟消息适配器、最小测试与中文运行说明。
- [ ] 默认 dry-run：识别新消息但不真实发送；仅允许预先配置的一个测试联系人。
- [ ] 真实发送前由用户明确确认接收方，核验当前会话身份；身份不确定时拒绝发送，不仅凭可能重名的昵称判断。
- [ ] 经用户明确启用后，向该联系人回复一条固定文本，不调用模型。
- [ ] 验证连续消息、重复事件、程序重启、客户端退出和联系人身份不确定时的行为。

需要持续可交互的 Windows 桌面时，明确说明具体运行条件，实测锁屏、最小化、远程桌面断开等状态；不要声称后台启动成功就代表能持续收发微信。

若当前版本不可用，提供兼容性证据、阻塞点和替代候选，不默默改成官方机器人入口。不得要求用户从不可信来源安装旧版客户端。

### 阶段 B：模型与连续对话

- [ ] 创建可替换模型接口；模型名、服务地址、超时、上下文预算和额度限制使用配置，不写死未经核验的值。
- [ ] 提供假模型用于离线测试，缺少真实凭据时仍能开发测试。
- [ ] 每位授权对话对象使用稳定、隔离的会话标识；处理连发消息的顺序问题。
- [ ] 设置可修改的称呼、语气、回复长度和交流偏好；不擅自假定用户希望恋爱角色扮演。
- [ ] 重启程序后可恢复必要会话状态；长历史采用有界窗口与摘要，避免无限发送全部历史。
- [ ] 只向模型发送本次回答必要的消息与记忆，不上传整台电脑或整个微信的聊天历史。
- [ ] 测试模型超时、鉴权失败、余额或额度错误、空回复和格式错误；避免无限重试、重复扣费和重复发送。

模型授权与费用：核验服务商当前支持的授权方式。开发 Codex 的订阅额度与运行聊天系统的模型调用授权必须分别说明；不要默认 ChatGPT 会员等于免费 API，也不要默认某种订阅授权允许任意后台代理用途。不抓取浏览器 Cookie、不提取账号会话令牌。

### 阶段 C：长期记忆

至少区分：

1. 当前会话：最近消息、正在讨论的主题。
2. 稳定偏好：称呼、交流习惯、兴趣、明确禁忌。
3. 事件与进度：用户提到的重要事情、计划、后续结果。

实现要求：

- [ ] 使用本地可备份的数据存储；首版可以选轻量存储，不为了形式强制引入向量数据库或多个服务。
- [ ] 每条长期记忆保留来源引用、创建与更新时间、类型、有效状态；区分明确事实、临时状态与待确认推测。
- [ ] 用户明确说“记住……”时建立稳定记忆；不能把“今天不想聊天”永久解释成“不喜欢聊天”。
- [ ] 用户明确更新偏好时，以新信息更新或取代旧信息；不继续同时使用相互冲突的事实。
- [ ] 回复前按相关性检索必要记忆；不知道时说明不确定，不编造过去的共同经历。
- [ ] 支持查看、纠正、删除某条记忆，以及经过确认后清空全部记忆。
- [ ] 删除须处理活动记忆、相关摘要、缓存、检索索引和可能重新提取该信息的源记录；不能只删一行之后又从旧历史“记回来”。
- [ ] 说明遗忘的实际范围。原微信聊天、旧备份、模型服务商留存等不能在未验证的情况下承诺同步清除；明确恢复旧备份时如何避免已删除记忆复活。
- [ ] 敏感信息不默认写入长期档案；日志默认不记录完整聊天正文，不记录任何密钥。
- [ ] 备份与恢复测试后，仍能正确使用有效记忆，并继续遵守已执行的遗忘要求。

验收示例均为测试数据，不代表用户的真实偏好：

- 测试用户说“记住：称呼我为小禾，回复尽量简短”。重启后检查是否仍使用该偏好。
- 改为“以后不要叫小禾，改叫阿禾”。确认后续不再使用旧称呼。
- “今天有些累，不想长聊”。不能将其写成永久性人格结论。
- 查询“你记住了什么”，返回可理解、可修改的条目。
- 删除某条偏好后，测试检索、摘要、重启和恢复流程，不重新引入该偏好。

### 阶段 D：持续运行与交付

- [ ] 实现安全启动、暂停、停止、状态检查和单实例保护。
- [ ] 持久化消息处理状态，过滤自身消息，避免回复循环；不对启动前的历史消息无差别补发。
- [ ] 发送前再次校验目标。出现发送结果不明时进入待核查状态，不盲目重发；不能声称不具备事务能力的界面操作能保证严格 exactly-once。
- [ ] 发现登录异常、会话不明或兼容性异常时停止真实发送，明确报告需本人处理的事项。
- [ ] 设置可配置的调用次数、并发数与费用保护。费用估计不能伪装成账单精确值。
- [ ] 提供 Windows 运行与诊断脚本、脱敏日志、备份恢复说明和常见故障排查。
- [ ] 自启动、计划任务、系统设置修改、付费订阅与安装授权须单独说明并取得必要授权。

## 7. 开发与验证方式

每个可独立验收的模块先编写测试，运行确认预期失败，再实现最小功能，重跑并记录结果。测试至少覆盖：

- 正常文字对话、中文与多行文本、重复事件、自身消息和非白名单消息。
- 重名联系人、意外切换窗口和目标身份无法确认：均不得发往错误对象。
- 连发消息顺序、断线、重启、历史消息和发送结果不明。
- 模型超时、配置缺失、额度保护与无法访问外部服务。
- 偏好持久化、更新覆盖、临时状态不固化、遗忘与备份恢复。
- 伪装成系统指令的聊天内容不能扩大权限、改变白名单或读取密钥。

不要把 mock 测试通过写成真实微信验证通过。每次阶段汇报分别列明：已创建的文件、实际执行的命令和结果、实机已验证项目、未验证或阻塞事项，以及确实需要用户完成的最小操作。

在授权工作目录内完成实现；不读取无关项目或批量扫描私人文件，不自动创建远程公开仓库，不上传真实聊天或凭据。
