# 本轮设计

需求：CODEX_TASK.md；用户明确要求本轮直接实现不依赖真实微信的部分。

采用 Python 3.11+ 标准库、SQLite、unittest。选择轻量本地服务而非强制 OpenClaw：减少配置和运行权限；模型通过可替换协议接入，记忆保持独立。未来对接 OpenClaw 时还需单独核验它的工具权限与远端记忆删除。

消息按到达顺序串行处理；稳定消息 ID 持久化去重，稳定联系人 ID 派生隔离会话。拒绝群聊、自身、非白名单、启动前历史和无法验证的身份。模型前、发送前及适配器发送内部校验身份。真实发送在本版不可开启；dry-run 不调用 send，关闭 dry-run 也只写模拟输出。

SQLite 分为 state.sqlite3（可恢复的记忆/会话/摘要）与 guard.sqlite3（不可回滚的去重、额度预留、遗忘账本）。崩溃留下的发送中状态转为待核查，不重发；其他处理中状态转为中断，不自动重试。不会宣称 UI 自动化具有 exactly-once。

稳定偏好仅由明确指令写入；事件以明确键值记录，临时聊天不做人格推断。记忆有类型、确定性、来源 ID、创建/更新时间、状态。同键更新替换旧值；更新/遗忘采用保守策略清理此前整个会话历史和摘要，保留无关的结构化记忆。不使用向量缓存。摘要是有来源的截断摘录，不是假装理解所有过去话题的语义摘要。

遗忘先写独立账本再清理内容；重启重放未应用的账本。备份仅含内容库，恢复必须提供同一 lineage 的最新 guard.sqlite3；缺失/不匹配则拒绝。旧账本被一起回滚无法被软件完全识别，文档必须说明；迁移前需复制最新账本。不会删除原微信、旧备份或服务商留存。

假模型用于全部离线验收；可选 Chat Completions HTTP 客户端需显式开启网络、本机提供密钥并配置完整 endpoint/model。没有浏览器授权抓取、订阅借用或自动重试。预算是本地调用上限和用户填写的估计金额，不是精确账单。

控制台模拟器支持启动、暂停、恢复、停止、状态；操作系统文件锁防止同一数据目录双实例。日志只记录固定代码与消息散列。Windows 脚本只启动项目，不安装微信、不改执行策略、不创建自启动。
