# 独立中继、目标自有寿命与持久终态整合

2026-10-12。本轮把此前分开的原生目标、独立中继、SQLite 接收协议和结束对账接成一条**自建进程、虚构数据**链路。启动控制器结束后，目标继续有限工作，中继继续提交；接收器可在提交前后崩溃重启；目标结束后，中继核验实际进程状态并提交持久终态。未接入产品或真实微信。

最终 13 类各 3 次，共 **39/39 通过**。36 个虚构数据库共 1347 行、36 个持久会话结束，终态后新增 0 行。249 个测试进程均有实际退出码，39 个目标完成自主清理，原调用合计 2328 次。1313 次成功 ACK 均有本中继此前收到的提交回执；提交后崩溃恢复产生 6 条去重记录。382 项产品离线测试通过。

## 新链路与信任范围

新原生变体沿用冻结的 Hook、固定 8 槽环缓冲、只读消费和目标自有寿命，只为消费者重启增加管道握手。目标接受 work 后不再读取启动 stdin；旧 stdin bind 已禁用。ACK 服务线程独占绑定句柄，查询实际连接 PID 和创建时间，核对目标身份、epoch 和本轮随机令牌。旧消费者已退出才能替换；即使旧消费者断开管道，只要仍存活，替换仍拒绝。

令牌随实验命令行传递，只是本轮合作夹具的准入条件，不能防御同用户恶意进程，也不证明授权中继不会伪造 ACK。目标、接收器和中继仍是可信实验参与者。

中继启动时恢复既有会话，开始后自行循环：只读批次 → 保存已观测上界 → 接收事务 COMMIT → 收到回执 → 原生 ACK。接收器实际退出后重启并核验原会话；提交后丢失回执时，重读批次会比较已存正文、去重，再产生提交后的 ACK。启动控制器 EOF 不取消已经开始的中继。

普通 I/O 错误不作为目标死亡证据。目标 PID/创建时间绑定由中继查询，接收器又在结束事务内核验。确认结束后，终态、持久游标、已观测未提交区间和 active 清除一起提交。全量已存会话重复对账返回原终态，不新增结束操作。

## 实际矩阵

下表是每类每次结果；每类均重复三次。普通目标工作为 64 次、每次间隔 40 ms，租约专项为 8 次。它们不是吞吐或延迟上限证明。

| 场景 | 实际结果 |
|---|---|
| 正常、仅控制器退出 | 64 行提交、64 ACK；控制器退出后目标继续原调用，中继自行结束 |
| 接收器提交前/后退出 | 仅结束接收器，中继重启它；64 行且无重复新增，提交后场景有去重 |
| 中继提交前/后退出 | 结束中继、桥接、接收器，目标仍活；新中继通过握手接管，64 行提交 |
| 控制器及全部辅助者在提交前退出 | 目标独自完成 64 次、发布 8 条、缺口 56；目标结束后新中继对账，库 0 行、已观测丢弃 1 条 |
| 控制器及全部辅助者在提交后退出 | 同样完成并清理；已有 1 行保留，ACK 为 0，之后结束会话 |
| 数据库忙锁 | 写锁持有到目标退出后才释放；0 行、0 ACK，随后对账成功 |
| 长时间忙锁 | 中继达到重试期限返回 deferred/2，锁在中继退出后才释放；目标早已自行完成，之后重启对账 |
| 实际 SQLITE_FULL | 限制页数后在接收事务内尝试真实扩页，错误码 13；事务回滚、0 ACK、deferred/2，原会话仍 active；之后重启对账 |
| 终态再次重启 | 重启中继返回完全相同的终态，结束操作只有一次 |
| 消费者租约 | 活旧消费者拒绝替换、错误令牌拒绝、旧消费者退出后允许正确后继；目标自主清理 |

最终退出码分布为 186 个 0、51 个指定故障注入的 1、6 个预期 deferred 的 2、6 个预期握手拒绝的 29。9 次控制器失联均有后续原调用，其中 6 次另外三个执行消费/提交/ACK 的辅助者也已结束。外层观察者仍存活；它保留创建时间核验的等待句柄，但不持有目标 stdin，不发送目标收尾命令，不靠外部清理把失败算成成功。

## 保留的失败与独立审计

缺实现预检真实失败单列保存。其后 61 项进程矩阵尝试中 53 项匹配、8 项失败：最早正常/接收器提交后场景各 1 项清理协议失败，以及两轮三类负对照的 6 项失败。旧文件、日志和数据库均未改写。

最早正常场景已完成工作和对账，但控制器 quit 未输出响应，测试按 EOF 失败；补充响应后通过。最早接收器重启也已成功提交终态，但结束已被杀接收器的 stdin 时，先前失败 resume 写入的缓冲再次报错，导致中继退出 1。修复仅允许在已经观察到子进程退出后记录这一关闭错误；没有修改退出码或吞掉活进程的写入错误。

负对照使用同一原生 EXE，并保留正确断言：提前 ACK 两次均在库 0 行时推进 acked=1、发布到 seq9；遗漏终态两次均留下 active 会话和 64 行；跳过令牌核验两次均错误接受错误令牌的新消费者。它们保持失败，不标为成功的 expected-failure。

独立审计不导入被测模块，重放原始命令/回执顺序，核对进程启动与真实退出记录、归档源码和 EXE 哈希。每个数据库连同 WAL/SHM 复制后只读检查，再比对原件哈希。全量 54 库 2052 行、52 个结束会话、381 个进程都已核对；0 条终态后新增，2 次提前 ACK 顺序违规仅来自负对照。原 65 研究源码、29 产品源码、24 分析脚本、362 证据以及 773 个冻结旧文件保持不变。

## 仍未证明的条件

全部 36 个最终终态证明都是 `same_process_signaled`。PID 缺席/复用、真实权限错误、枚举截断没有因此通过。没有可信生产者最终高水位，所有终态仍保留 `tail_unknown=true`；最终共 6 条已观测未提交记录被关闭协议丢弃，不代表所有外部副本物理消失。取得接收事务锁并检查存活后，目标仍可在 COMMIT 前退出；保证的是终态事务后的写入屏障，不是 OS 死亡与 SQLite 提交原子化。

这是有限合作工作量和有界重试实验。未覆盖任意启动/重连竞争、外部删除或改名数据库、恶意 IPC、任意对象寿命和生产监督策略；12 秒循环期限也不是包含 OS/管道调度的严格完成上限。满载停采不会因为后来的 ACK 自动恢复。旧断点双角色失败保持失败；真实身份/ABI、共享写异常、热装卸和 CFG/CET 仍未证明，475 不构成实机注入授权。

下一项在**新的自建变体**验证真实共享槽写指令访问异常和部分写入后的发布隔离，区分写故障与已有指定读故障，不能扩大成任意异常吞掉。继续保留未知尾部、旧失败及冻结源码。

产品仍为 0.1.22，自动回复关闭、旧监听停止；本轮没有微信、窗口、密钥、聊天库、发送、模型、子代理或新工作树操作。id40 此前暂停状态保持。
