## 记录与异常边界

Hook先把四个已知按值参数复制到32字节本地候选，原函数经实际跳板返回后才调用固定容量发布器。外层原函数调用位于采集`__except`范围之外；整个外层使用`__finally`恢复线程内深度标记。测试用重入调用发生在外层采集范围内，其原函数异常必须依靠过滤器继续向外传播。重入时只转发原调用，跳过该层采集；本次正常重入中的虚构id900000确实未入库，这个策略会漏掉嵌套候选，不等于完整消息交付。

捕获过滤器同时检查访问违例类型、读操作、异常指令位于自建复制函数、读取地址位于本次自建NOACCESS页。其余异常继续搜索处理器。复制函数是无局部栈区的32字节汇编叶函数，拥有静态展开记录；保护页来自本进程新申请的8192字节内存，第二页不可访问。没有输入外部PID、任意用户指针或读取微信对象。

首项读取故障位于复制函数偏移0；跨页部分复制在偏移14的第三次读取故障，此前已执行前16字节复制。失败候选不交给publish。只有这个指定故障点和地址组合被处理，不能将范围校验当成通用指针生命周期验证。

目标仍合作启动安装、全部调用结束后才恢复入口、注销三项动态函数表、确认查表为空并释放页/映射/保护页。最终24个目标都记录这些清理成功。此次没有在跳板不同PC触发异步异常，也没有热卸载测试。

## 最终矩阵

每个场景执行后再执行一次正常调用；检查深度为0、加权返回无错误、Hook进入/返回计数、消费者输出和SQLite允许行。

| 首次场景 | 次数 | 两次操作完成后的结果 |
|---|---:|---|
| 正常 | 3 | 两次原返回，两条记录 |
| 复制首项失败 | 3 | 采集停用，两次原返回，发布0、入库0 |
| 复制16字节后失败 | 3 | offset14读故障；两次原返回，部分候选不发布 |
| 原返回后、发布前读故障 | 3 | 原结果保留，两次原返回，发布0、入库0 |
| 发布后读故障 | 3 | 缓冲仍有1条；采集停用后消费者拒绝，测试入库0 |
| 原函数故障 | 3 | 故障继续到外层SEH；下一正常调用返回并发布id1 |
| 正常重入 | 3 | 包含嵌套调用的3次原返回；只发布外层id1和后续id2 |
| 重入中的原函数故障 | 3 | 嵌套异常穿过采集过滤器，外层未调用原函数；深度恢复，下一正常id2发布为seq1 |

最终Hook进入54次、成功原返回45次、窄范围采集异常12次、向外传播的原函数异常6次、重入跳过采集6次。原返回计数在Hook收到返回值后增加，不是原函数体内的独立计数。共发布21条，其中3条属于发布后故障的已停用会话；本轮消费者均在故障后读取，所以它们未入库。

最后一个事实不能扩展成“发布后故障可撤销任何交付”：若其他消费者在停用前已接受或写入记录，本轮没有验证撤回，也没有实现撤回。之前的STOP和迟到ACK限制仍适用。

72个最终子进程（24目标、24只读消费者、24SQLite接收进程）全部正常退出0，无强制结束。24库18行的独立`mode=ro&immutable=1`审计通过，全部会话关闭，提交号在STOP之前，序号连续、字段与预期虚构id一致；其中重入故障后的id2对应seq1，没有错误假设id等于seq。审计前后哈希不变，无WAL/SHM遗留。约3.434秒是总场景时间，不是Hook时延上限。
