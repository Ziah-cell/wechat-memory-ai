# Windows 后续执行清单

本页是下一轮真实微信接入与实机验收的交接，不表示已经完成真实微信通道。v0.1.1 已在用户 Windows 电脑完成离线核心验证。

## 已完成的 Windows 步骤

1. 校验已有解压目录：60 个文件与原 ZIP 一致，59 项 manifest 哈希一致。
2. Windows 11 build 26200，Python 3.12.14；修复原套件 2 项失败与脚本缺少 py 的问题。
3. 诊断保持 mock / fake / dry_run=true / network_enabled=false。
4. 在临时数据目录完成“记住 → 退出重启 → 纠正 → 查看 → 备份 → 遗忘 → 重启 → 恢复旧备份后不复活”的模拟验收。
5. 已检测客户端文件版本 4.1.15.13。免费候选仅声明支持到 4.1.8.107，真实接入仍被兼容性证据不足阻塞。

## 现在如何运行与继续

在项目目录执行 `.\scripts\windows.ps1 -Action run`。脚本自动寻找可用 Python，也可用 `-Python` 指定，不需要先安装 py。测试用 `-Action test`，诊断用 `-Action diagnose`。

用户已确认只考虑免费适配器。按 [FREE_ROUTE.md](FREE_ROUTE.md) 优先验证正常 UI 自动化；需要用户本人启动微信并扫码登录受控的第二个普通个人号，再核验 UI 可访问性与唯一测试好友。不要把密码、API Key、二维码或整个聊天数据库发到聊天中。阶段完成后直接更新同一 GitHub 仓库，不再下载修订 ZIP。

| 场景 | 当前结果 | Windows 需记录 |

## 遇到问题

- `config_error`：检查 TOML 格式、单个 mock 身份、布尔值是否误写为字符串，或真实模型是否缺少本机凭据。
- `already_running`：先运行 status / stop；不要删除锁文件。异常退出时操作系统会释放锁。
- `identity_blocked`：模拟/未来适配器身份不匹配；核查实际目标后再本地 resume。
- `model_failed`：查看 audit.log 的固定错误代码；本条不会自动重试。核查后由用户重新发一条消息。
- `unknown` / `review_required`：停止应用，运行 `review` 查看事件散列；实际人工核查后用 `review --resolve 散列 --outcome sent` 或 `not_sent` 标记。任何标记都不会自动重发原消息。
- `budget_blocked`：本地次数/估算上限已到；不要把它解释成真实账单余额。失败调用也保留预留。
- `guard_missing` / `guard_lineage_mismatch`：找回同一数据集最新 guard；不要使用其他项目的账本或删除保护文件来继续运行。
