## v0.1.0 历史计划正文

> **For agentic workers:** 使用 superpowers:executing-plans 在本会话逐项实现。用户已要求直接开发和运行测试；不再增加需求批准环节。

**Goal:** 交付可离线运行、有记忆和发送保护的模拟聊天核心与 Windows 交接包。

**Architecture:** 串行编排器连接可替换适配器、模型和本地 SQLite。内容备份与不可回滚的安全账本分离。

**Tech Stack:** Python >=3.11，SQLite，unittest，TOML；无第三方运行依赖。

**Spec:** CODEX_TASK.md、docs/DESIGN.md 与本轮范围。

## Global Constraints

- 真实微信发送关闭，本版不可启用；离线核心的 mock / HTTP 本地测试与本轮真实窗口只读验收分别记录。
- 2026-10-02只读实机增量：已完成目标数量等待、明确超时原因及普通观察模式的显式零秒持续等待（v0.1.10，189项历史回归）。1003/1004到达过程没有捕获，不能由后来可见补记通过；1005后来由原v0.1.10会话捕获2来信候选并正常结束，见159。真实观察与mock Engine保持分离，dry_run本身并不阻止模型或记忆操作。
- v0.1.11历史增量：已定位一类整批前景采样证据全零，并在原基线内最多三次重取；60次实机检查观察到一次二次捕获恢复。181项选定回归通过，13项原生测试未重跑；升级当时保留1005旧会话基线，其后已完成，不再作为活动进程。
- v0.1.12只读预检用每次基线后新生成的验证文字阻挡标记前候选，标记整批丢弃，后续只返回来信方向候选。它仍无可信到底信号，不证明身份或历史新鲜性，必须有人监督且不浏览历史；只允许1–3600秒有限等待，结束关闭且重启需新标记。实机正向预检已完成关闭（177），v0.1.13新增显式绑定的消息源，尚未接入Engine、模型、记忆或发送。
- 不要求在聊天提交密码/API Key；不装微信、不读取私人目录。
- 单联系人白名单、并发数 1、不自动重试、不使用运行时工具。
- 使用稳定消息 ID，不用正文散列合并合法的相同文本。
- 遗忘清理历史和摘要；恢复保留最新账本；日志不含正文/密钥。
