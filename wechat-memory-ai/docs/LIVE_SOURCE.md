## 实现范围

`ReadOnlyWeChatSource`必须显式接收已授权窗口实例的完整绑定（进程、启动时间、窗口、根、列表），不能在构造时省略约束或在失败后改选当前唯一窗口。`NativeReader`将该约束用于第一次原生调用；既有C#绑定检查在遍历消息和读取Name之前执行。绑定只在内存中传递，不写入日志、配置或Git；它是本次窗口实例约束，不是跨重启的联系人身份认证。

消息源只在上下文管理器内工作，每次poll调用同一个联合读取器和PreflightSession。基线、随机标记、整批丢弃、未知/自身过滤和连续性规则沿用已有实现。每个源限制1–3600秒；到期、关闭或读取失败立即终止，不自动重建绑定、恢复或积压回放。消费方只能串行调用；不提供后台线程、队列或重连。

返回独立的`LiveCandidate`，字段明确区分本地观察编号、本地观察时间、会话标识与正文。正文和会话标识不出现在repr或状态报告中；不提供虚构的服务器消息ID或服务器发送时间。候选不会转换为模拟适配器的Event，也不会进入Engine。`is_current`仅表示对象仍属于当前未关闭源，不代表发送许可。

消息源没有可用发送操作，调用send必须明确拒绝且没有外部副作用。模型、SQLite和记忆模块不被导入。关闭之后先前交付的对象仍是调用方持有的普通内存值，但`is_current`必须失效；不能声称能够撤回已交付内容。

## 验证与限制

使用纯Python虚构快照验证：首调用携带指定绑定、绑定副本不可被外部修改、缺少约束拒绝；基线与标记批次不交付、后续重复文本保持两条、自身/未知被排除、停止和到期失效、有限时间与上下文清理、发送明确拒绝、报告脱敏。既有原生夹具排除范围不变，不为本功能重跑被拒动作。

早期193只做有约束的新基线及关闭检查，189只做已可见自身消息方向与共享过滤的组件检查；它们本身不等于同一个已解锁会话中的自身新事件验收。后续224补验的具体范围见顶部，不需要无故重复已通过的输入。

此消息源仍限同一窗口、可见、不最小化、有人监督且不翻历史。发送方身份、任意历史同步、跨重启去重、锁屏/RDP和无人值守运行未由这些字段证明。实际发送适配器和模型/记忆接入仍需后续实施，当前封装不代表自动回复已就绪。
