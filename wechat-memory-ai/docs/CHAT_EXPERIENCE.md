# 自然聊天、延迟与记忆的接入要求

2026-10-03用户新增要求：延迟不高、少AI腔、能接续聊天并记住偏好，像平常聊天一样交流。本文件记录产品要求与实现进度。v0.1.15已完成虚构对话的真实API小样本评估，并修复其中暴露的有限饮品回忆路径；整体聊天质量尚未通过，微信消息源与实际记忆/自动回复仍未接通。

## 已评估的模型与延迟

本轮使用`deepseek-flash`的非思考模式。2026-10-03核对的官方模型为DeepSeek-V4.1-Flash；Chat Completions支持显式`thinking.type=disabled`，默认则开启思考。来源：[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[请求格式](https://api-docs.deepseek.com/api/create-chat-completion/)。模型别名不保证永远指向同一版本。

专用适配明确关闭思考，输出上限映射为`max_tokens`，不传`store`或`reasoning_effort`。用户已填写本机密钥，评估使用独立、被Git忽略的本机配置；主配置及仓库示例保持fake、关闭网络。请求契约与配置边界见[DEEPSEEK.md](DEEPSEEK.md)。

[204](evidence/204-live-model-synthetic-evaluation.json)的6次调用和[206](evidence/206-live-model-style-follow-up.json)的2次复测均技术成功，完整模型请求耗时0.697–2.390秒；不是微信端到端延迟，也不能据小样本承诺固定秒数。评估仅使用已清理的临时Store和虚构对话，未操作微信或实际聊天记忆。本轮已结束，不再调用API。后续仍以单次回复调用、有限上下文及相关记忆控制开销，避免回复前再串行调用模型整理记忆。

首轮[205风格审查](evidence/205-live-model-style-review.json)发现遗忘回答过多解释内部过程；提示调整后的206却编造了不存在的偏好，并进一步声称该偏好已删除。此项质量失败保留，不能用8次请求成功代替自然度或记忆可靠性验收。

## 聊天风格

- 日常消息优先一到三句，随话题和用户消息长度调整；用户询问复杂问题或要求详细说明时展开，不硬截断成残句。
- 承接当前话题，不每轮重复招呼、复述问题、列清单、做总结或问“还有什么可以帮助你”。
- 不主动做说教和心理分析；是否给建议取决于用户是在闲聊、吐槽还是求解。
- 只有有用时才提及旧事和偏好，不每次说“根据你的偏好”；没有记录就不编造共同经历。
- 口语、语气词和表情保持适度，跟随用户偏好，不靠故意错别字或随机延迟伪装真人。
- 允许温暖自然的交流，保持真实身份表述；不擅自设定恋爱关系或虚构现实行动。

虚构的风格例子：已知样例用户偏好清淡，询问晚饭时，可以说“来碗番茄鸡蛋面怎么样，清淡一点。”不必先解释记忆系统如何检索。这只是测试样例，不是实际用户偏好。

## 记忆分层与修正

近期对话负责接续正在说的话；较早的重要话题需要带来源的摘要；稳定偏好和明确的重要经历单独持久保存，按当前话题取用。模型更换不应删除本地记忆。云模型生成时需要接收本轮正文和选中的上下文；本地保存不表示这些片段从不发送给服务商。

用户不应必须每次输入命令才能被记住。后续可从明确的日常表达提取低风险偏好，例如虚构样例“我喝咖啡不加糖”，记录原话来源、时间和确定程度；不能从一次情绪、玩笑、引用或模型自己的回复推断稳定人格。模糊信息保持候选，矛盾事实不同时当作真，新的明确纠正覆盖旧值。敏感信息不自动形成长期资料。

“别再记这个”“我现在改了”等自然修正应可作用于对应记忆；删除同时清理会话上下文、相关摘要及后续派生结果，并遵守独立遗忘账本，不能从旧备份或迟到的提取结果重新写回。明确的查看、纠正和删除入口继续保留。

## 已有能力与下一步

当前`Engine.context`能组合配置中的语气/风格、结构化记忆、旧历史摘录和近期对话，按字符预算裁剪。自然聊天规则已加入系统提示，配置、当前明确要求和更新后的偏好可以调整默认风格；206表明这些提示不足以阻止模型猜测。DeepSeek专用分支拒绝截断或超长回复，原通用分支仍保留字符裁剪。旧摘要只是有来源的截断摘录，不能称为语义总结或完整聊天记忆。

v0.1.15新增有限的完整饮品回忆及保存状态问句：直接查询当前会话`active`、`explicit`、`preference`记录，只认`饮品偏好`、`饮料偏好`、`饮品喜好`、`饮料喜好`四个键别名。无记录就说明不确定或当前未保存，多条相关记录不任选；单条忠实陈述保存内容，不升级成“最爱”。状态回答只说明现有记录，不推断曾经删除；assistant历史和摘要不能成为该查询的事实来源。12项回归及[213独立审查](evidence/213-memory-recall-review.json)通过，普通推荐和未匹配的复杂问法仍走原模型流程。

明确记忆指令、纠正和遗忘仍可用，但自动提取日常偏好、一般事实回忆和自然度验收尚未完成；不能把局部确定性查询视为全主题防编造能力。上述核心只在模拟适配器工作，`ReadOnlyWeChatSource`不会把真实候选送入其中。真实记忆与自动回复接通仍受当前阶段边界约束。
