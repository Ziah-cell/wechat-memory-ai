## 时序记录

`background` 原生子进程在固定边界向私有 stderr 管道写入 `wmrd1:<固定阶段>:<累计毫秒>` 并刷新。stdout 快照协议不变。无正文、窗口名称、绑定、坐标、异常原文或截图；其他读取方式没有原生阶段记录。

阶段依次为 `started`、`request_read`、`client_lookup`、`process_lookup`、`window_lookup`、`binding_check`、`tree_lookup`、`list_binding`、`rows_first`、`binding_middle`、`rows_second`、`rows_compare`、`binding_final`、`snapshot_ready`、`serializing`、`completed`。

每个时间点表示**开始该阶段**，相邻时间点之差包含前一阶段的执行及诊断开销。`completed` 表示 stdout 已刷新，不表示 Python 验证、会话接受、方向验证或可回复。超时后最后阶段只是最后成功写出的检查点，不能定位到单个 UIA 方法。没有有效记录时显示 `not_reported`，不能推定原生程序完全没有启动。

`NativeReader.diagnostics` 和常驻状态的 `reader_diagnostics` 暴露：

| 字段 | 含义 |
| --- | --- |
| `child_calls` / `child_timeouts` | 子调用尝试数 / `subprocess.TimeoutExpired` 次数；包括失败尝试 |
| `last_call_ms` / `max_call_ms` | 最近子调用 / 本 Reader 最慢子调用的墙钟耗时，包含启动、通信及结束清理 |
| `last_call_timed_out` | 最近子调用是否触发子进程超时 |
| `native_trace_valid` | 最近 stderr 是否是合法固定序列前缀 |
| `last_native_stage` | 最近子调用的最后已报告阶段，或 `not_reported` |
| `native_checkpoints_ms` | 仅最近子调用的固定阶段及累计毫秒；不会沿用前一次成功记录 |
| `slowest_call` | v0.1.20新增：本Reader首次取得最高耗时的子调用序号、耗时、超时布尔值及同次阶段。尚未调用或旧状态没有保存时为null |

`slowest_call`字段为`child_call`、`call_ms`、`timed_out`及与最近记录同样严格脱敏的三个阶段字段。只保留一个固定大小记录，后续严格更慢的调用才替换，毫秒舍入后相同则保留较早者。成功、超时和系统调用失败都可成为最慢记录；记录不表示快照已接受，不包含消息序号、身份或正文。出口复核调用序号不超过累计次数、耗时等于有效`max_call_ms`；不一致则返回null。返回字典和嵌套阶段字典均独立复制。

旧v0.1.19进程不会热更新此字段，新状态查询只会对它显示`slowest_call=null`，不能从最近阶段追补旧最慢调用。该进程现已超时停止，保留284故障证据后可显式启动新会话，新的非空视口仍只作基线；不追认旧会话未完成的到达测试。

Python 只接受不超过 4096 字节、完整换行、按序且不重复的阶段前缀；时间必须非负、单调不减且不超过 24 小时。异常、未知、截断或畸形记录全部丢弃，不影响既有快照判定。读取器和状态出口均重建白名单字段，不透传字典或管道内容。状态报告始终复制嵌套字典。

子调用计时使用独立的性能时钟，不增加既有 8 秒共享预算。若子进程成功结束，但 Python 在共享期限后才检查结果，仍会停止且不交付；此时 `stop_reason=native_reader_timeout`，但 `child_timeouts` 可以为 0。这与操作系统子调用超时是不同边界。计数不是微信事件数。编译耗时不计入 `child_calls`。

## 恢复决策

| 观察到的情况 | 当前行为 | 原因与限制 |
| --- | --- | --- |
| 已绑定读取的前后快照不一致 | 相同绑定、原 8 秒内最多 3 次子调用 | 中间失败不更新会话；成功结果仍需连续锚点 |
| 首次未绑定读取变化 | 停止 | 没有可依赖的既有绑定 |
| 子进程超时、其他原生或协议错误 | 停止并关闭 Reader；不自动重启 | 不能以延长超时或隐式重建基线掩盖数据缺口 |
| 窗口、进程、启动时间、根或列表变化 | 停止 | 新目标没有沿用旧授权/连续性的依据 |
| 视口失去连续锚点 | 会话终止，之后旧锚点回来也不恢复 | 无法区分翻历史、重建控件或缺失新事件 |
| 显式重新启动 | 首个非空视口仅作新基线 | 重启基线中已可见文本全部跳过；后续补入的历史仍可能计为unknown，不承诺补处理或跨重启去重 |
| 新文本、自身文本或同步历史出现在后台列表 | 全部 `unknown`，仅计数 | 本模式不能可靠区分三者，不得进入 Preflight/Source/Engine |

4096 容量、旧组合重现拒绝、绑定与双读规则保留。这里验证的是拒绝和隔离边界，没有实现无人值守自动恢复、可靠收发方向或身份验证。
