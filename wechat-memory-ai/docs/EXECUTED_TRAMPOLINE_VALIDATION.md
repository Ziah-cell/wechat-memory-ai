# 自建跳板实际执行与异常传播

2026-10-10。最终自建Windows x64程序在12类场景各3次、共36次检查中通过六参数转发、返回值、所选四个非易失寄存器、异常传播和合作清理检查。这里的Hook只计数，没有连接原生发布器、SQLite接收表、产品Engine或真实微信。完整原始结果见[520](evidence/520-executed-trampoline-results.json)，构建见[519](evidence/519-executed-trampoline-basis.json)，保留状态见[521](evidence/521-executed-trampoline-checkpoint.json)。

## 实际执行路径

新增[C夹具](experiments/executed_trampoline_fixture.c)、[汇编调用者](experiments/trampoline_register_caller.S)和[测试驱动](experiments/test_executed_trampoline.py)。使用已校验的本地Zig 0.14.1，以Windows x64、O2、Wall/Wextra/Werror编译；四次构建均退出0，无编译警告。各次源码、编译参数、诊断、EXE和哈希在忽略目录归档，证据JSON内保存构建清单及运行原文。没有安装全局工具链。

每个子进程申请自己的4096字节页，生成两个原函数、两个跳板和两个中转。Hook安装前不存在调用线程，入口的固定五字节压栈前缀被E9改成到同页中转的相对跳转。中转用R11跳至编译好的C Hook；Hook用已知签名调用跳板，跳板复制四次压栈后跳回原函数+5。原函数执行余部并返回到Hook，Hook再返回调用者。只有被动关闭采集计数，没有运行时卸载。

页面初始化为RW，写完切换RX并检查FlushInstructionCache；合作安装/恢复也只在无调用线程时暂切RW。六项动态函数表注册后逐项查找匹配；全部调用和工作线程结束后恢复两处原始前缀、注销表、逐项确认查表为空、释放页。最终36个子进程每个都记录了这些成功结果并退出0。故障对照崩溃的进程没有这些清理确认，不能补记为正常清理。

原函数前九字节为四次压栈及sub rsp,8，形成40字节栈区；第五、六参数在此时RSP+80/+88。跳板仅复制五字节压栈，随后执行mov r11,imm64与不带REX.W的jmp r11，共18字节。这里把跳板SizeOfProlog设为18，与此前虚构上下文实验的五字节序言不是同一配置。原函数展开信息包含8字节分配和四个压栈槽，中转使用叶函数记录。没有复用微信原函数的完整展开表。

这些设计依据[Microsoft x64调用约定](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170)、[x64异常展开](https://learn.microsoft.com/en-us/cpp/build/exception-handling-x64?view=msvc-170)、[VirtualProtect](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualprotect)和[SEH try-except](https://learn.microsoft.com/en-us/cpp/cpp/try-except-statement?view=msvc-170)。文档契约与本机实际运行结果分开，不把文档存在当作测试通过。

## 最终检查范围

| 场景 | 每轮状态 | 最终次数 | 检查内容 |
|---|---|---:|---|
| 整数 | baseline / hooked / stopped | 9 | 六个uint64参数按1、3、5、7、11、13加权；返回RAX及四寄存器哨兵 |
| 浮点 | baseline / hooked / stopped | 9 | 每进程128组可精确表示的double，六参数同样按位置加权，返回值逐组比较 |
| 原函数异常 | baseline / hooked / stopped | 9 | 自建原函数访问空指针；异常现场的一步展开副本正确，外层SEH接住，再次正常调用 |
| 安装后并发 | hooked / stopped | 6 | 四线程各5000次加权整数调用，线程全部完成后再核对计数与哨兵 |
| 被动关闭转换 | stopped | 3 | 安装后启用计数调用一次，再关闭计数调用一次；转发2次而采集仅1次 |

按测试调用路径计，最终36次共发起121200次原函数调用，其中9次故意触发异常，其余返回；实际Hook计数为入口120804次、返回120798次、采集60402次。1152组浮点输入覆盖寄存器及栈参数；24个工作线程均结束并关闭句柄。没有测得延迟上限，也没有并发STOP或热安装竞态验收。

汇编调用者设定RBP、R14、RSI、RDI四个完整64位哨兵，生成函数保存后故意覆写这些寄存器；正常返回检查哨兵和整数结果。该调用者自身有静态SEH展开信息。检查范围不包括全部非易失寄存器、XMM6–15、混合签名、变参、结构体返回、C++异常或其他ABI。

异常观察器仅识别自建整数函数地址范围内的访问违例，在CONTEXT副本上调用RtlVirtualUnwind，比较四寄存器、RSP与RIP；预期RSP前移48字节（40字节局部区加返回地址）。它不改OS的原上下文，不吞异常，返回CONTINUE_SEARCH。随后原异常穿过实际调用链到外层SEH；Hook异常进入计数增加，返回计数不增加。9次正式场景的一步副本均为mask63、RSP差48，并完成捕获和再次调用。

## 失败与检查缺口保留

十批共103项记录，89项符合当时断言、14项失败；不写成103项通过。共实际启动102个原生子进程（首次缺文件未启动），已记录92次退出0、6次访问违例退出、1次不支持新场景退出2、3次浮点预期不匹配退出9。较早驱动未记录PID，但subprocess.run已收取退出码；最终36个子进程逐个记录PID、退出及无存活子进程。没有超时或由本轮驱动强制结束的子进程。

缺RBP对照同时从原函数和跳板的展开描述去掉该槽，不修改执行中的push/pop。普通返回依旧正确，所以普通调用通过不能验证异常信息。最终三种异常状态在观察副本中都得到mask14、RSP差40：少恢复8字节，RBP和RIP错误。基线OS分派最终仍进入SEH，但一步恢复已错；其后操作系统如何继续走到处理器未做内部跟踪，不能据此声称损坏展开表仍安全。两种Hook状态在过滤器前以0xc0000005退出。驱动始终要求异常恢复正确，没有改成expected-failure。

首版浮点函数只做求和，参数互换可能不改变结果。自查后先改预期并保存3次失败，再改生成字节按位置加权；最终运行绑定新的源码和EXE，没有把先前36次补算为加权检查。

## 尚未解决与后续

本轮只实际执行固定已知函数和固定可复制前缀，不是通用反汇编/指令重定位库。异常只发生于原函数余部；虽然跳板实际执行，但没有证明跳板每个PC上的异步异常处理，也没有对这份18字节序言配置复做此前的六点虚构展开实验。CFG/CET、热安装/卸载、新线程安装竞态、对象指针寿命、采集故障隔离、所有辅助者丢失与长时间运行都未验证。

下一项可在同一自建链路中集成已知ABI的跳板、固定容量发布器和虚构持久接收表，检查消费者退出、积压与STOP提交顺序；必须另存集成版本，保留现有单组件证据。当前Hook中的采集只是原子计数，不提供消息记录，也没有持续环形队列。

旧硬件断点双角色退出失败保持。475外部断点许可不能扩展成实机DLL注入或代码改写。本轮无微信附加、DLL加载、窗口操作、密钥/聊天库访问、真实发送或判断模型调用。产品0.1.22、自动回复关闭、旧监听停止；旧35份研究、29份产品、24份分析脚本和335份证据哈希保持。

本轮已知额度剩余15%，id40保持此前暂停。报告与证据是本阶段进度，不是最小化微信自动回复已可交付的声明。
