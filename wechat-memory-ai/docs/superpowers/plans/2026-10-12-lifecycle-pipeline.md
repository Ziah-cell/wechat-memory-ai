# 独立接收、目标自有寿命与终态整合

仅在新自建变体和虚构库中工作，保留冻结源码、失败与旧数据库。沿用 implementation 提交推送授权，不用子代理、新工作树、真实微信、模型或自动化。

1. 先保存缺实现的真实失败。新原生协议为独立桥接重启提供握手：连接 PID/创建时间由 OS 查询，目标身份/epoch/本轮随机令牌须匹配；活旧消费者不能替换。令牌通过实验命令行提供，不声称能防御同用户恶意进程。目标工作开始后不重新依赖 stdin。
2. 新中继自行只读取批次、保存观测上界、COMMIT、ACK，并在目标结束后提交终态。启动控制器 EOF 不取消已启动中继。接收器崩溃可重建；已提交但未 ACK 的批次重放去重。
3. 目标结束或 ACK 管道在退出时断开，转入真实进程状态核验与终态对账，不能把普通 I/O 错误解释为目标已死。锁忙可重试，有界期限后明确 deferred；存储错误不能通过提前 ACK 隐藏。
4. 验证控制器退出、接收器提交前后退出、中继及全部辅助者退出/重启、目标自行完成、真实锁忙与 SQLITE_FULL。外层仍是观察者和故障注入者，不持有目标 stdin、不补做目标清理。
5. 保留错误令牌绕过、提前 ACK、遗漏终态等负对照。最终重复矩阵、独立原始日志/退出码/SQLite审计、离线回归、自审、546–548证据和报告、检查点、提交推送。

范围仍是有限合作工作量。无可信最终高水位时尾部未知；对账不是 OS 死亡与数据库提交的原子操作。PID缺席/复用/真实权限故障等未覆盖分支不能沿用其他分支冒充通过。
