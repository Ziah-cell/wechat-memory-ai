# 发布器异常停用与释放顺序

2026-10-11；已有继续开发授权。所有输入、目标、共享记录和数据库均为自建虚构数据。旧源码及证据冻结，新增独立变体与驱动。

1. 先写正确行为断言，缺实现失败留档。假设：持门异常展开只释放门、等外层处理器才停用时，第二个生产者可在窗口中发布；消费者甚至能在处理器执行前接受并写入虚构接收表。
2. 从 publisher_gate_tls_fixture.c 另存复现变体，先不修复。四个故障点各配两种第二生产者：窗口后进入的新调用、窗口前已复制候选且原函数已返回的调用。事件只负责固定测试交错；线程1释放门后暂停，线程2完成，控制器通过真实只读消费者读取并交给真实SQLite接收器，再放行线程1。
3. 不因预期错误而改断言；完整保存窗口状态、第二线程是否尝试/取得门、实际批次及接收表。复现后最小修复：持门区异常退出先将状态改为INVALID，再释放门。正常退出不停止采集，外层窄过滤器仍只处理自身受保护读点，原函数异常继续传播。
4. 初始11类各3次通过后，自审扩展第三种位置：第二生产者已通过发布器首次状态检查、尚未取得门。验证它即使随后取得门，门内状态复核仍会拒绝发布。最终同一EXE提供 late_stop 故障对照和 skip_recheck 对照，分别省略提前停用、门内复核；正确行为断言必须失败。最终矩阵为12个交错加正常、直接原异常、嵌套原异常，共15类各3次。检查全部原返回、线程深度恢复、游标边界、消费者/持久行以及合作清理。
5. 运行离线项目测试，独立只读审计所有最终数据库及失败复现中的泄漏行。保存完整运行与失败记录、旧文件哈希、报告和检查点，再提交推送。
