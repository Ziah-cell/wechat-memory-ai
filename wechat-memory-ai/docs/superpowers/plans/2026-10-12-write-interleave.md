# 真实写异常的确定交错

仅新自建进程、虚构数据；继续既有授权，提交并推送 implementation。旧源码、证据、失败和缓存冻结。产品 0.1.22 和关闭的实机入口保持。

1. 新派生 Hook 在七个真实槽写点注入只读页写 AV。测试事件分别停在过滤器决定、finally 停用尚未解锁、解锁尚未外层处理三个位置。第二生产者分别从新进入、候选已准备、首次状态检查通过三个位置继续。
2. 在每一暂停位置调用独立命名管道 ACK 服务、只读消费者；8 条已提交前缀只 ACK 7 条，检查持门时 busy、解锁后合法前缀 ACK、停用后无半写输出。消费者跨阶段挂起的游标也必须重新检查状态。
3. 在第一个线程待写 TLS 仍有效时，由另一个测试线程在相同 PC、相同故障地址触发真实写 AV，分别没有 armed 或 armed 了错误地址。不得借用第一线程的授权。测试外层观察器只接住这些已知故障，不算生产处理。
4. 负对照：延迟停用、删除门内状态复核、把 TLS 待写上下文换成共享上下文。断言按正确行为执行，失败保留。每次编译和运行独立归档，最终矩阵各重复三次。
5. SQLite 提交先于 ACK，目标正常退出后 reconcile；只读副本核对数据库、原始阶段/故障/进程日志和哈希。运行现有离线产品测试，写报告和 552–554 检查点，核对远端和干净工作区。

测试控制器负责释放事件，故本阶段不重新证明控制器失联、自主寿命、吞吐或暂停上限；映射有效、控制页可写仍为前提。消费者停用不能撤销此前已合法接受的数据。无真实微信、窗口、密钥、聊天库、发送、模型、子代理、新工作树操作。
