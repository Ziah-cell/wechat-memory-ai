# 目标自有有限寿命验证

沿用自建进程、虚构数据与 implementation 提交推送授权。无子代理、新工作树、真实微信操作或模型调用。旧阶段源码、失败、数据库和报告冻结。

1. 先保存旧 stdin EOF 行为的实际失败：真正结束嵌套启动控制器，目标未完成预定原调用就收尾。外层只观察并保存稳定进程句柄，不持有目标输入管道。
2. 新独立原生变体在接受有限 work 后封闭控制入口，工作线程与 ACK 服务归目标持有；目标等待自己的工作完成后先 join，再还原入口、删除展开表、释放资源。启动控制器 PID/创建时间只用于身份验证及失联观测，不作为寿命持有者。启动前 EOF 安全收尾；启动后 EOF 不取消任务。控制器存活且管道不关闭时也应自行结束。
3. 验证正常退出、强制结束、单独 EOF、提交前/后事务暂停时控制器消失及所有辅助者结束。接收端关闭连接回滚未提交事务，提交后保留。目标不等待持久化或外部清理，明确易失记录丢失边界。
4. 同一 EXE 保留 EOF 停工、控制器失联停工和漏删展开表的负对照，按正确断言保存失败。保留固定环缓冲、身份/epoch ACK、COMMIT 先于 ACK、原异常传播及停用/写门顺序。
5. 对最终源码重复关键矩阵；独立只读审核原始日志、退出码、数据库与哈希，再跑离线产品回归。完成自审、540–542证据、报告、只读恢复入口及提交推送。

范围仅是合作启动的有限工作量夹具。外层观察者仍存活，无无限驻留、任意对象寿命、共享写异常、热装卸、CFG/CET 或真实微信 ABI/身份结论。产品自动回复关闭，旧监听停止，id40 不变。
