# 自建采集异常与重入计划

沿用上一轮交接和用户继续授权，在implementation分支新增独立变体；旧40研究、29产品、24分析、341证据保持。自行实施与审查，不调用其他判断模型或代理。

目标是验证新集成Hook的记录边界：先复制已知按值参数到本地候选，原函数成功返回后才发布。原函数异常不进入采集错误处理；重入时跳过采集仍转发，外层finally恢复线程标记。此变更只属于新实验，不改上一轮成功/失败记录。

采集故障用自建两页内存及汇编32字节复制函数制造；第二页NOACCESS。异常处理器只接住代码地址落在此复制函数、读地址落在本次保护页内的访问违例。比较首项读取失败、复制16字节后失败、原返回后/发布后失败。发布后失败只能停止后续接受，不能撤销其他消费者可能已接受的记录。

1. 新驱动先保存缺实现失败。
2. 从集成入口另存新变体，加入窄范围SEH、原异常传播、线程内重入标记及finally清理；新增叶函数汇编复制点。
3. 8类各3次：正常、四种采集故障、原函数故障、正常重入、重入原函数故障。每例后续再正常调用；独立消费者/SQLite核对允许记录。
4. 同一EXE启用过宽捕获过滤器作为故障对照，原断言应检出被吞掉的嵌套原函数异常；不改expected-failure。
5. 核验清理、SQLite与来源，保存525起证据、报告、提交推送、交接。

限制：只测试指定自建读故障，不能声称任意指针/内存损坏安全；未在旧publisher持锁写入内部注入异常。无并发/多线程TLS验收、持续队列、热装卸、CFG/CET、真实微信ABI或实机采集。本轮仍由Python控制器驱动，不是常驻生产接收服务。
