# 目标结束后的持久会话终态

继续既有自建夹具与 implementation 提交推送授权；无实机、模型、子代理、新工作树或自动化。上一阶段全部冻结，复用其原生 EXE 作为自建目标，不重跑旧脚本。

1. 新建独立接收协议和 SQLite 实验库，先保存缺实现/旧行为的真实失败。
2. begin 验证本机目标 PID/创建时间；reconcile 自行查询该绑定状态。活目标不能结束会话，查询不确定不能假定目标已死。终态、操作号、持久游标、已观测却未提交区间和清除 active epoch 在一个事务中完成。
3. 不存在可信最终高水位，终态始终标记尾部未知；已观测但未持久化的序号范围只表示本协议在关闭后丢弃，不能声称所有副本物理消失。外部输入与虚构载荷仍来自受信测试桥接，不构成生产身份认证。
4. active 会话提交回执后才可 ACK；提交后崩溃重放去重。结束后 accept 拒绝，包括旧 epoch；独立 replay 仅核对已存完全相同的批次且不产生 ACK，也不能插入缺失记录。
5. 测试真正的目标/接收器进程退出、关闭事务提交前后崩溃、并发 accept/reconcile、SQLite 锁忙和真实 SQLITE_FULL。接受事务已经取得写锁并检查目标存活后，目标仍可在 COMMIT 前退出；只承诺事务关闭屏障，不虚构跨 OS/SQLite 的原子死亡时刻。
6. 保留错误死亡判断、漏关 epoch、错误完整性标记和漏核对重放载荷等负对照。最终重复矩阵、独立 DB/WAL/SHM 与日志审计、离线产品回归、自审、543–545证据和报告、检查点及推送。

原生生命期机制和真实接入门槛不变。本阶段会话收尾是事后恢复操作，不是目标继续运行或清理资源的依赖。不会修改上一阶段残留的真实实验数据库来假装它们当时已经正确关闭。
