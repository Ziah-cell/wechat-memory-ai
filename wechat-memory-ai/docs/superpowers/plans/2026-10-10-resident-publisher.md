# 自建常驻发布器实施计划

2026-10-10。沿用既有自建实验、开发和提交推送授权，在 implementation 原工作区执行；不创建工作树、任务或调用其他判断模型。

目标：以真实编译的 Windows x64 子进程验证资源所有权。目标直接调用同一可执行文件中的发布函数，消费者只映射只读页。没有 Hook、DLL 注入、热安装或真实微信数据。

## 设计裁定

- 固定8条、每条32字节虚构载荷；单会话只追加、不覆写、不循环复用。消费者不回写游标，目标不等待消费者。满载、发布者竞争或无效长度使本会话停止发布，原函数仍被调用。
- 目标持有映射及发布代码直至自身结束；消费者存活可能使内核映射对象继续存在，但不能使目标依赖消费者的地址、句柄或代码。
- 128位随机会话代次、目标 PID 与进程创建时间绑定。创建时若同名映射已存在，拒绝复用。消费者核验目标进程仍存活与状态，停止后丢弃未提交副本。
- 不声称状态复核能撤回已接受/已进入输出管道的记录；提交后再发生停止仍有竞态。这里只输出虚构候选，实际交付端撤销屏障留作独立问题。
- 无系统范围的硬延迟保证；记录耗时，区分“回调不显式等待外部进程”与“调度、缺页或故障均有硬上限”。

## 步骤

1. 编写原生进程行为驱动 `docs/experiments/test_resident_publisher.py`，先用缺失实现确认测试未被误当作成功。保存每次源版本、命令和完整失败。
2. 独立忽略目录固定 Zig 0.14.1，按官方索引 SHA256 校验，仅编译本项目 C 源 `resident_publisher_fixture.c`。回调路径不分配、打印、等待、查询进程或做文件/网络 IO。
3. 验证正常顺序与去重、容量满、只读保护、无效载荷、竞争、停止前后、复制与提交间停止/目标退出、消费者正常退出/被杀/不响应、旧代次及同名映射拒绝、目标退出后的映射寿命。原函数返回值及自主工作线程进度必须实测。
4. 对失败做最小修复并保留旧版本；仅因修改或新增具体风险重跑相关矩阵。不重跑未改产品与旧断点套件。
5. 只读校验旧31研究/29产品/24分析/329证据哈希，保存513起新证据、报告、当前索引和 HANDOFF；自查边界，提交推送并核对远端。
