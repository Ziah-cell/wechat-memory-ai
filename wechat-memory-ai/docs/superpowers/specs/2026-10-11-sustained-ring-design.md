# 自建固定内存持续缓冲协议

2026-10-11。目的：验证自建已知 ABI 跳板链能在消费者确认持久提交后多圈复用固定内存；不接产品、微信或真实数据。依据交接直接实施、自行审查，不使用子代理，不新建 worktree、不改分支。

## 选择

采用固定8槽环及累计 ACK。无限队列违背固定内存；覆盖最旧项不能保证未确认记录保留；阻塞生产者违背原调用不等待。满载或写门竞争直接停止本采集会话，成功原返回数减已发布数公开缺口，不自动恢复。持久表可以增长，固定内存约束针对目标发布器。

## 协议

每个目标进程使用全新32位十六进制 epoch，整个生命周期不重置。seq 从1单调增加，限制小于2^62以防 stamp 溢出；槽号为(seq-1)%8，槽代次 generation=(seq-1)//8+1。共享页恰好4096字节，8个槽；published 与 acked 单调且 0<=acked<=published。原函数成功返回后才发布。容量判断 published-acked==8 时停采，禁止写槽。

ACK 为(epoch, seq, generation)，只有虚构 SQLite 接收器 COMMIT 成功才产生；测试控制器是受信转发边界。原生控制线程验证 epoch、代次、单调范围和对应槽 stamp，再用写门更新 acked。ACK不在Hook内处理，Hook不等待消费者、数据库或控制线程；门竞争停采。协议没有加密认证，不能抵御受信控制器伪造已提交ACK。

持久接收表按(epoch,seq)唯一，提交连续前缀、校验槽代次及虚构负载、精确重复去重、内容冲突和序号缺口拒绝；行和游标在同一个 FULL/WAL 事务。提交前崩溃重试插入，提交后ACK丢失重试去重。STOP关闭表会话后不接纳新记录，旧成功ACK可能迟到。目标退出丢失尚未落库的易失记录，不称为端到端完整交付。

消费者只读映射，并绑定目标PID/创建时间/epoch。槽使用全原子字段和前后stamp校验，避免复用时混读；写入时先发布奇数stamp，记录完成后偶数stamp，再推进published。使用本机Windows x64已验证的lock-free原子，不能外推为可移植跨进程C内存模型。每次读取从acked+1取最多8条，输出不推进ACK；断线重连可重放。FULL/BUSY/STOPPED允许排空此前有效记录，INVALID拒绝。消费者与接收表间旧批次仍依赖持久端校验。

异常路径保留持门异常先INVALID后释放、门内状态复核、窄复制异常过滤和原函数异常传播。测试插桩可以阻塞工作线程暴露交错，不属于无阻塞时延证明。保留冻结源码，新增独立C协议、消费者、Hook变体、接收表和驱动。

## 验收与边界

真实编译执行多于容量的多圈记录；ACK丢失、重复/旧会话/旧槽代次/未来ACK；消费者强制退出、SQLite提交前后强制退出、忙锁和实际SQLITE_FULL；满载不覆盖且原返回继续；混读检测；复用后持门异常交错、原异常传播。负对照覆盖跳过容量检查、跳过ACK代次检查、跳过读stamp检查、异常停用顺序/门内复核。负对照仍使用正确断言失败。
