# 自建跳板、发布器与持久接收表的集成检查

2026-10-11。新自建原生程序实际执行改写入口、C Hook、跳板和原函数，并在Hook中将四个虚构参数发布到固定8条映射；独立只读消费者输出后，由Python测试控制器交给SQLite接收进程。最终14类各3次共42次通过。它是受控组件集成实验，没有接入真实微信或产品自动回复。

构建与来源见[522](evidence/522-integrated-receive-basis.json)，全部运行及独立数据库审计见[523](evidence/523-integrated-receive-results.json)，保留状态见[524](evidence/524-integrated-receive-checkpoint.json)。本轮只有[新C集成入口](experiments/integrated_receive_fixture.c)和[新测试驱动](experiments/test_integrated_receive.py)两份研究源码，之前38份研究、29份产品、24份分析脚本和338份证据保持。

## 实现边界

C集成入口以编译期包含方式复用[发布器](experiments/resident_publisher_fixture.c)及[跳板辅助函数](experiments/executed_trampoline_fixture.c)，将两者原有测试main重命名；新main不调用这两个入口。构建清单记录所有包含文件和汇编依赖的哈希。仍用已校验的本地Zig 0.14.1，Windows x64、O2、Wall/Wextra/Werror；一次构建退出0，无警告。

新Hook签名为六个uint64参数。前四项组成32字节本地数组，分别为id、id XOR固定常数、id+7、id×3；第五项为已知长度、第六项为固定测试参数。Hook将本地数组交给旧publish，然后调用跳板；调用者独立比较六参数的加权返回值。状态字段`original`在Hook拿到返回值后增加，代表成功转发返回次数，不是原函数体内的独立计数器。

消费者和SQLite进程无需注入目标，Hook也不等待其响应。只在启动时、尚无调用线程时安装；所有工作线程join后才恢复入口、删除三项动态函数表、检查查表为空、释放生成页及目标映射。39次正常目标退出都有这些成功确认；3次强制结束目标没有合作清理记录，不能补记为已执行还原代码。

停止由测试控制器先提交接收表STOP，收到成功ACK后再请求原生停止。因此外部旧批次在持久边界关闭后被拒绝；这不是跨进程原子STOP，也不是已实现的常驻控制服务。若接收表忙，返回busy，不会把它报告成已停止。此前提交的成功ACK仍可晚于STOP ACK到达，已有行不会撤回。

旧SQLite模块路径限制保持；本轮新库都在`data/resident-delivery-20261010/integrated-20261011/`下唯一运行子目录，没有打开旧实验数据库进行写入。新构建/日志/交接在`data/integrated-receive-20261011/`。

| 满缓冲 | 3 | 前8条已提交；继续51次调用后仍返回正常，缓冲不增长且采集停止 |

最终147个子进程（42目标、48消费者、57接收表）全部退出：126次正常退出0，21次由驱动强制结束退出1。强制结束包括3目标、6消费者、12接收表。18个工作线程完成，最终状态累积12327次成功转发返回，返回值错误为0。总场景时间约10.489秒，不是Hook调用延迟、停止时间或硬实时保证。

42个最终数据库独立以`mode=ro&immutable=1`打开，共81行；integrity_check通过、游标连续、全部会话已关闭，所有行的commit_op均小于该会话stop_op。审计前后文件哈希不变，最终无WAL/SHM遗留。这个顺序结论依赖同一个SQLite事务与操作号，不是跨进程时钟同步或网络发送恰好一次证明。

skip_publish对照仍得到3次或8次成功原调用、错误计数0，但发布条数为0，驱动在预期批次/发布条数处失败。没有把这两个失败改成expected-failure；它说明当前断言能发现发布路径被跳过，不代表覆盖全部采集错误。

## 保留的限制和下一项

Python测试控制器全程存活，消费者和接收表结束为有顺序的独立操作；本轮没有证明所有辅助进程同时消失后的行为。四线程只在安装完成后启动，未验证热安装或并发卸载。满8条/写门竞争就停采，没有缓冲重用、持续消费背压或可靠长期流。

数据是已知按值参数的本地拷贝，epoch由可信测试控制器分配，仍不是微信身份/方向/服务器消息ID。发布发生在原函数返回前，不能将发布记录解释成原函数已接受真实消息。本轮没有给新集成Hook注入原函数异常、采集自身异常或重入，也不能把上轮另一个Hook的异常测试移算到此版本。

下一项先在自建集成Hook验证采集自身故障、原函数异常与重入对转发和记录边界的影响；持续缓冲需要另行设计。未知对象指针寿命、CFG/CET、真实微信ABI与实机安装授权仍是独立门槛。旧硬件断点双角色退出失败未解决，不沿用475外部断点许可执行实机注入。

产品仍0.1.22，自动回复关闭，旧监听保存停止。无微信附加、DLL注入、窗口操作、密钥/聊天库访问、真实发送或判断模型调用。最新已知额度剩余7%，id40保持此前暂停，未使用重置额度。
