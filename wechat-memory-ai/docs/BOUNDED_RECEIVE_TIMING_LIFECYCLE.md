# 停顿预算与完整夹具生命周期集成

2026-10-09。沿用[既有授权](evidence/475-bounded-receive-authorization.json)，将[停顿区间检查](BOUNDED_RECEIVE_PAUSE_TIMING.md)接入[36类生命周期矩阵](BOUNDED_RECEIVE_GUARDED_THREADS.md)。最终每类3次，**108次预期行为检查通过**：93次目标继续运行，12次保留原有致命异常退出，3次主动正常退出。仅操作自建夹具，微信准入仍关闭。

## 本轮改变

新增[集成观察器](experiments/receive_probe_lifecycle.py)，继承已有计时观察器，把每次等待事件的请求片段限制为最多5毫秒；清理使用的零等待保持为零。实际返回时间仍受系统调度影响，不能据此保证5毫秒唤醒。原20份相关源码全部保留。

结果增加运行时区间摘要，区分观察/恢复角色真正掌握的历史与测试控制器事后掌握的结束进程时间。运行时发现未闭合、历史缺失或超预算时，保持丢弃候选记录；测试端不能替恢复角色补造已知边界。

新增[输出同步夹具](experiments/receive_probe_lifecycle_fixture.py)，只将原并行夹具的JSON输出置于同一锁内，保留原生函数、异常行为和自主并行调用。[新矩阵](experiments/test_receive_probe_timing_lifecycle.py)记录损坏输出数量，并将其判为失败；诊断保存不再因JSON损坏而直接抛出异常。

## 实测失败与修正

[499研究记录](evidence/499-bounded-receive-lifecycle-basis.json)保存以下过程，未覆盖旧结果：

1. 首轮36次中35次通过。空闲150毫秒后匹配时，原50毫秒等待片带来的保守单段上界为101.126毫秒，记录被正确丢弃，但正常匹配目标没有达成。下界仅约0.436毫秒，不能把上界当作真实暂停。缩短等待请求后，3次定向复测上界约22–28毫秒；最终矩阵的3次约26–30毫秒，均完成匹配。
2. 接着一批原计划108次的运行，前102次结果通过并已落盘；第103次（`owner_rapid`，第1次）在诊断保存时发生 `JSONDecodeError: Extra data`，整批退出1。该次结果未完整保存，记为未知，不能补算通过。并行线程的 `print` 可在JSON文本与换行之间交错；带主动让出执行机会的离线复现同样失败。新增夹具输出锁后复现通过，并补充损坏输出计数检查。
3. 冻结/清槽后观察进程退出的6次，恢复角色没有控制器的结束进程时间，因此仍报告 `pause_timing_unknown`。测试端合并自身时间戳可以闭合区间，但这一事后结论不会升级运行时结果。这是证据范围的区别，未放宽预算。

## 最终核查

运行 `python docs/experiments/test_receive_probe_timing_lifecycle.py --repeat 3`，退出0。36类覆盖主/新线程、线程退出与反复创建、匹配/布局拒绝、空闲超时、取消、命中上限、并行/快速调用、观察角色和恢复角色分别退出、附加中途、冻结/清槽/解冻/脱离边界，以及自定义异常、应用断点、UD2和正常目标退出。

| 计数维度 | 结果 |
| --- | --- |
| 预期生命周期与计时政策检查 | 108/108通过 |
| 继续运行的目标 | 93；检查新的主/新线程调用及连续心跳，并行场景要求3个工作线程完成 |
| 保留原致命退出 | 12；应用断点6次，UD2 6次 |
| 主动正常退出 | 3 |
| 合并测试端记录后的区间判定 | 64次在保守上界内；33次已知下界超限；11次无法认证 |
| 主要结果为超上界拒绝 | 44；无可用记录 |
| 主要结果为计时未知拒绝 | 6；无可用记录 |
| 完成有界标记匹配 | 12；HMAC投影，方向/来源仍为unknown |

[500结果](evidence/500-bounded-receive-lifecycle-results.json)列出每次结果和计时分类。故障恢复仍故意延迟200毫秒，超限检查通过是指正确识别并清理，**不代表恢复满足100毫秒预算**。运行时6次未知与测试端部分可闭合的结论保留各自口径。

这轮矩阵沿用并行夹具的调用、心跳和退出码检查，**没有采集上一轮计时夹具的独立执行时钟点**；“执行点与停止区间无矛盾”不是本轮额外证明。区间计算仍是观察器日志推导的上下界，没有精确测量内核暂停，也没有建立跨机器的硬实时保证。同步日志/API阻塞与第三方Native接口兼容性仍待处理。

[501核查](evidence/501-bounded-receive-lifecycle-validation.json)绑定4批249条完整原生结果（248通过、1失败），另保留1次未完整落盘的中断；最终108次同一版本结果及各角色运行时区间均重新计算核对。25份相关源码有哈希绑定，旧20份相关源码、29份产品源码、24份历史脚本及315份旧证据保持。未重跑产品回归、原始完整原生套件或上一轮36项专门延迟注入套件。
