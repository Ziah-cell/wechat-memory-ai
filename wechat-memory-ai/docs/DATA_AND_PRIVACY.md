# 数据、记忆与遗忘边界

## 文件与恢复关系

| 位置 | 内容 | 恢复规则 |
|---|---|---|
| state.sqlite3 | 有限会话、摘录摘要、最多 100 条/会话的结构化记忆 | 可用项目备份恢复 |
| guard.sqlite3 | 来源事件散列/状态、调用预留、遗忘序列、确认码哈希、库身份 | 只能保留最新副本，不能随旧内容回滚 |
| audit.log | 固定元数据代码、时间、散列 | 不含正文；不参与模型上下文 |
| runtime.json / control.json / instance.lock | 进程控制和实例锁 | 不含正文/密钥；不参与模型上下文 |
| .env | 可选本机凭据 | 不属于备份、版本库或模型输入 |

来源引用是持久化事件记录的散列键。记忆管理原话不长期保留，事件元数据可用于确认来源与处理状态，不能用于重建已遗忘的正文。

普通会话仅保留最近配置数量的消息；更早内容生成有来源 ID 的有限摘录。摘录是文字截断，不保证保留所有语义与话题。没有外部向量服务、自动文件扫描或聊天历史导入。

## 删除和纠正

内容写入和删除使用 guard 中持久化的单调逻辑时间（尽量接近 UTC 纳秒，系统回拨时自动递增）。先把删除要求写入 guard，再清理内容，确保中途退出后可以重新应用，也避免系统时间回拨跳过删除。删除条目时：清除该记忆、此前本会话的所有历史与摘要；同会话其他结构化记忆保留。同键纠正也清理旧历史，避免模型继续见到过期值。聊天 Agent 不能直接写 SQLite，只有代码解析的显式命令能修改记忆。

清空操作需会话绑定的短期确认码；确认成功后清空该会话全部长期记忆、此前历史和摘要。后续只会留下不含已删正文的操作确认。没有独立检索缓存或索引，因此无需另外删除向量。

本版采用固定规则拒绝保存常见密码、密钥、手机号、证件、病历等疑似敏感输入；不能承诺识别所有敏感信息或各种变形。普通姓名/称呼与兴趣本来就是功能需要的用户自愿输入。敏感识别触发时不持久化原文，也不调用模型。

这不是磁盘取证级销毁。SQLite secure_delete 有助于清理删除页，但不能证明 SSD、操作系统快照、临时系统文件或外部副本已经擦除。本机程序无法替你删除原微信聊天、已导出的旧 ZIP、手工拷贝、其他设备或模型服务商记录。

## 旧备份防复活

内容备份包含 lineage、SHA-256 校验和与备份时的遗忘序号。恢复前校验内容库的完整性、必需表结构和元数据，空库/损坏清单不会被当作新项目初始化。恢复工具校验最新 guard 的相同 lineage 与足够新的序号，先在临时库应用尚未执行的遗忘，再替换内容库。去重和用量记录不来自旧内容备份，因此不会随内容回滚。

**必须保持最新 guard。** 若内容库与 guard 同时被人为回滚到更早副本，程序没有远端权威账本可证明其遗漏了之后的删除。不能承诺这种情况下仍能识别所有丢失的遗忘要求。建议把停止程序后的最新 guard 独立保存，删除旧数据备份/系统快照时由本人处理。若最新 guard 丢失，现有内容库会拒绝继续打开；不要删除文件来绕过错误，先找回最新副本或明确建立新的空数据目录。

恢复旧备份可能少掉备份后才创建的新事实；这比恢复已明确否定的旧事实更符合隐私意图。例如旧备份有“小禾”、之后改成“阿禾”，恢复时旧“小禾”会被移除，新“阿禾”如果不在该备份内则需要重新录入。

恢复操作要求关闭其他实例。CLI 获取同一操作系统锁；底层 Python 函数供开发者调用时也必须遵守这个约定。

## 模型与权限

只发送本次必要资料：固定角色、相关记忆、有限摘录、有限历史和当前消息。所有记忆与摘录以资料消息传递，不提升为系统指令。模型仅返回字符串，没有运行 shell、打开文件、读环境变量、改白名单或给任意联系人发信的工具。

这能约束本地程序的能力，并不能保证大模型永远不受文本诱导或不产生错误回复。若把 endpoint 指向具有自主工具能力的远端 Agent，其服务器权限必须单独收紧；本版没有对 OpenClaw 进行这类接入验证。
