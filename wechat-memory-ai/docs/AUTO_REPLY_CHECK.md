## 下一阶段顺序

1. 取得并验证最小化状态下的收发方向和目标身份依据，明确如何拒绝历史、过期来源及绑定变化。不能拿昵称前缀或本地观察时间充当身份/服务器时间。
2. 基于这些依据实现真实消息到回复核心的连接，先用隔离测试证明自身、unknown、历史和失效来源不会调用模型或写记忆。不能给LiveCandidate拼上mock身份、当前时间和`is_self=False`直接交给Engine。
3. 实现目标绑定的真实发送适配器，发送前重新核对窗口/目标，结果不明确时停止并等待核查。`ReadOnlyWeChatSource.is_current`只确认对象来自未关闭、未到期来源，不重新读取当前窗口，不能充当发送许可。
4. 使用虚构内容复验模型质量，完成可审阅的真实回复配置和发送方案后，再按既有约定取得实际自动回复的最终确认。

`dry_run`仍可能调用模型并写记忆，并非真实聊天的纯观察开关。当前保持background只读监听、防待机开启和真实自动回复关闭；不为检查发送而打断现有基线。
