## 最小记录格式与有限观察顺序

设计记录字段：`build_hash / run_id / sequence / logical_request_token / attempt_token / task_token / retry_remaining / monotonic_elapsed / stage / object_token / parent_token / thread_token / context_kind / executor_table_rva / raw_timeout / raw_backoff / certified_unit / state_before / state_after / outcome / missing_evidence`。阶段须区分注册、取出、回调开始/退出及移除返回；每次会话重新分配对象编号。不保存原始地址、昵称、账号ID、正文、完整响应、数据库内容或密钥。协议字段如不能脱敏且保留可验证关联，先停在设计阶段。静态证据中的DLL RVA是代码位置，不是活跃对象地址。

1. **离线准备（当前范围）**：保持固定输入，优先文字最终输出/通知及逻辑请求→内部尝试→任务/目标对应，补其他重试/异常、上游身份、实际receiver/scope和退出链；标清unknown，不加载DLL。385–388及本方案交付的是这一步的进展。
2. **有界只读观察（尚未授权/未实现）**：方法和前置条件具备后，方案建议一次最多5分钟或200条元数据事件，以先到者结束；无适配器发送、模型或记忆写入。预算是拟议采集上限，不是微信超时值。必须先有真实最小化状态与单账号/单目标的可信限定，不能沿用停止文件代替。
3. **一次受控发送（尚未授权/未执行）**：仅在前述缺口满足且具体发送获批后，执行一次固定中文文本，分别记提交、解析、业务响应、对端观察。任何结果不明保留unknown并结束，不通过重试“验证成功”。
4. **退出审阅**：核对事件顺序、遗漏/重复、所有权清理和观察器退出；缺少任一条件即标本次未通过，记录具体缺口。之后才讨论来源桥接与更长时间运行。自动回复仍需既有最终明确确认。

以上是下一阶段局部验证方案，不替代项目既定路线。Web、Bot/iLink/ClawBot、企业微信、公众号和旧版偏移均不作为本方案替代方案；不恢复窗口、不重启原监听、不执行已排除原生测试。
